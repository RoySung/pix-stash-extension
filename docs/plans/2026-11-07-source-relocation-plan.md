# 素材來源回訪與定位：完整計畫

日期：2026-11-07

狀態：首版功能已實作並完成自動驗證；Firefox 原生附加元件與外部網站人工矩陣仍待驗收。資源上限與搜尋預算仍是保守初值，非成功率保證。

實作與驗證紀錄：[2026-11-08 驗證紀錄](../source-relocation-validation.md)。

## 1. 問題與目標

目前收藏主要保存分頁網址。當素材位於照片列表、搜尋結果、彈窗或動態載入頁面時，回到同一網址仍需要重新尋找。Sportag 活動照片列表是代表情境，但本功能不得依賴網站名稱、特定網站 selector 或私有 API。

目標是保存收藏當下的定位線索，回訪時用有順序的通用規則尋找相同素材或截圖區塊。圖片收藏、區域截圖及可視畫面截圖共用定位模型；擷取方式依收藏模式不同。

成功結果分三級：

- **找到素材／區塊**：有足夠證據，捲動並短暫標示。
- **回到收藏附近**：只有位置或較弱線索，不宣稱找到原素材。
- **無法定位**：保留正常開啟來源的結果，提供縮圖與已保存的找回線索。

通用適用代表規則與流程可重用，不代表所有網站都能成功。未載入或已刪除內容、登入狀態、虛擬列表、canvas、跨來源 iframe 等都有降級路徑。

## 2. 範圍與設計決策

首版包含通用 DOM 擷取、圖片與文字比對、多定位點、位置恢復、有限度動態搜尋、圖庫與預覽入口、狀態提示及舊資料相容。

本次不做網站專屬規則、不自動操作購買或登入、不重播任意點擊、不自動提交搜尋或篩選表單、不無限捲動、不依靠整頁主圖推定截圖內容。OCR、像素相似度、跨來源 iframe 和 closed shadow root 的深度擷取保留為後續擴充。

直接連結與定位規則分開處理：連結決定開啟目的地，定位規則確認目的地上的素材；點擊圖片附近的連結不代表已找到素材。首版預設仍回到原收藏頁面，避免猜測詳細頁造成錯誤導向。

## 4. 收藏時擷取

### 4.1 統一目標範圍

| 收藏方式 | 目標範圍與策略 |
| --- | --- |
| 右鍵圖片 | 記錄最近一次 contextmenu 的目標元素，以圖片網址、分頁／frame 與事件時效確認後擷取；無法確認時只用瀏覽器提供的圖片網址 |
| 頁面圖片 | 將候選網址對回 DOM 圖片；相同網址有多個實例時標記歧義；只有 meta 圖片時保留 URL 線索，不虛構位置 |
| 區域截圖 | 擷取與框選矩形實際相交的圖片、文字及相關容器；以交集與辨識度選定位點 |
| 可視畫面截圖 | 擷取可見視窗內分散的多個定位點，以內容區為優先，避免全部來自導覽列 |

所有幾何資訊以 CSS pixels 記錄，截圖實體像素與 devicePixelRatio 分開處理。截圖與線索綁定同一個 tab、文件、網址與短效 capture token；收藏過程若切換分頁、導覽或幾何狀態改變，應重取或捨棄失效線索。區域截圖前確認來源分頁仍為活動分頁，避免截到其他分頁。

收集需在截圖前後最接近的時點完成；區域模式在使用者確認後、擴充套件選取 UI 隱藏時收集。排除 PixStash overlay、toast 與標示元素。不能假設 DOM 與截圖完全原子同步；失配時降低線索可信度。

### 4.2 線索內容

- 圖片：`currentSrc`、`src`、`srcset` 的已解析候選、已存在的延遲載入網址、alt、尺寸及範圍內相對位置。CSS 背景圖片也可取得已解析的 URL，但不掃描整頁樣式表。
- 文字：目標範圍內的可見短文字、標題、最少量前後文。文字節點用 Range 的矩形判定，不將整個大型父容器文字全部保存。
- 元素：唯一 ID、語意 role、具辨識度的屬性、有限長度結構路徑。動態 class、純索引 selector、看似隨機的 ID 僅作弱線索。
- 關聯：最近合理容器、區塊標題、圖片所屬連結；不保存任意祖先的所有連結。
- 位置：頂層及相關可捲動容器的 scroll offset、可捲動比例、視窗尺寸、目標矩形、定位點相對於截圖的位置。
- 頁面狀態：完整來源網址及 hash；僅保存附近可見的篩選標籤作人工線索，不自動重播表單。

位置同時記錄絕對值與比例，但比例不能作內容身份證明。文字正規化保留原文；合併空白及常見 Unicode 差異，不破壞中文、數字及大小寫有意義的識別資訊。

### 4.3 資源與資料邊界

初始預算：最多 12 個定位點、每個文字片段 200 字元、文字總量 2,000 字元、定位資料序列化後 32 KiB、同步擷取總預算 150 ms。以增量與可中止遍歷控制大型 DOM；超限時刪弱線索並記錄 truncated，不截斷 JSON。

不收集密碼、輸入框值、contenteditable 內容、隱藏文字或整頁 HTML。不複製 cookie、token 或網路請求內容。現有來源／圖片網址可能帶簽章參數，僅保存必要候選，不擴大收集；除錯輸出遮蔽敏感 URL 參數及文字。

線索擷取失敗或超時不應阻止原本收藏；照常保存圖片／截圖，標記線索不足。資料只存本機，不加入第三方 OCR 或分析服務。

## 5. 資料模型與相容

在 `ItemRecord` 新增可選的 `sourceLocator`，不用 `metadata: Record<string, string>` 塞入未定義 JSON。

建議結構：

- `version: 1`、`capturedAt`、`captureMode`、`truncated`。
- `page`：來源網址與頁面身份資訊；可選的已觀察連結候選及其依據。
- `viewport`、`captureRect`：視窗、框選與目標相對位置。
- `scrollContexts`：頂層／內層捲動容器的定位線索、offset 與比例。
- `anchors[]`：圖片／文字／元素型別、證據、矩形、相對位置、品質標記；每個定位點可包含多種證據。

不持久保存 DOM 引用、暫時 tab ID 或進行中的搜尋狀態。所有外部訊息與已存資料做版本、大小、數值、URL scheme 和字串驗證；不直接以不受信任文字組成 selector。

可選欄位不需要新增 store 或 index，預設不升 IndexedDB 版本。既有 v1／v2 升級路徑與所有 normalize／更新函式須確認不會丟失該欄位。舊資料缺少線索時，圖片收藏可用 `originalImageUrl` 嘗試基本比對；截圖維持正常開啟來源，不聲稱能還原收藏時位置。

定位資料隨 item 刪除；既有去重命中時不默默覆蓋舊定位資料，以免圖片、來源與位置對不上。後續若要更新既有收藏的定位資料，需另定明確規則。

## 6. 通用定位規則

按以下優先順序產生候選，再交叉確認。低級規則可補強高級規則；高級規則命中但有矛盾時不可提前宣告成功。

| 順序 | 規則 | 確認與降級 |
| --- | --- | --- |
| 1 | 原頁既有 hash／素材錨點、唯一元素 ID | 比對圖片、文字或其他內容證據；只有 ID 相同仍不足 |
| 2 | 完整圖片網址 | 搜尋已載入 DOM 圖片、srcset 與背景圖片；重複圖需上下文區分 |
| 3 | 圖片的保守變體 | 同來源、同路徑且只差明確尺寸／格式參數，或同元素 srcset 提供的已知變體；保留其餘身份參數 |
| 4 | 有辨識度的可見文字 | 精確文字與前後文先行，再做受限的正規化比對；短詞、價格、日期不能單獨確認 |
| 5 | 多定位點的區塊關聯 | 圖片、標題及鄰近定位點的共同容器和相對分布支持同一區塊 |
| 6 | 結構路徑與周邊資訊 | 用作候選提示和其他規則佐證，不能只靠 nth-child 成功 |
| 7 | 捲動位置 | 恢復頂層與可識別的內層容器；結果最多是「附近」 |

完整 query、photo ID、簽章參數不可一律移除；檔名相同但路徑不同不視為同一圖。正規化規則以可辨識參數的語意為限，模糊變體必須有其他證據。

直接連結：首版可記錄及提供 HTTP(S) 候選作備援，禁止自動執行 javascript URL、表單或任意事件。未驗證的周邊連結不自動取代原來源。若未來支援自動直達，必須額外證明其對應同素材並保留回原頁路徑。

### 6.1 可信度與歧義

首版採可解釋的分級門檻，不將未校準的數字當作機率：

- **可靠**：唯一的完整圖片匹配且上下文無矛盾；或唯一元素／文字匹配加另一項獨立內容證據；或至少兩個有辨識度的定位點共同支持同一區塊。
- **歧義**：重複圖片／文字、多個相近候選、或只有相同 DOM 屬性衍生的多項證據。不算獨立佐證，不自動選第一個。
- **附近**：只有結構或位置可信，可恢復附近但不能成功標示某張素材。

負向證據也要納入，例如圖片不同、區塊標題矛盾、anchor 分布不一致。固定頁首／導覽中的重複定位點降低權重。第一版不自動開啟網站彈窗；找到頁面上的縮圖即可標示，無法還原的彈窗提供提示。

## 7. 回訪執行與動態頁面

### 7.1 工作生命週期

1. 使用者從圖庫或預覽啟動來源回訪，背景取得 item，建立新分頁並綁定一次性定位工作。
2. 工作以 request ID、item ID、tab ID、預期文件與網址、期限識別。頁面準備好後，以 content-script ready handshake 發送線索，避免依賴任意固定延遲。
3. content script 掃描已載入內容，匹配、等待必要 DOM 變化，再按預算嘗試搜尋。
4. 結果為 found／nearby／ambiguous／not-found／unsupported／cancelled；UI 對應呈現。
5. 成功、取消、到期、分頁關閉或無關導覽後清理工作、observer、timer 與標示。

背景使用 `storage.session` 保存短效工作，避免 service worker 休眠後遺失；若目標瀏覽器不支援則採明確記憶體降級並顯示可重試。頁面只能取得綁定該 sender tab／frame 的工作；不透過來源 URL query 或 hash 傳遞 item ID、定位內容或憑證。

首版以頂層與可安全存取的同來源 DOM 為主，偵測但不穿透跨來源 iframe；open shadow root 的遍歷需遵守同一預算，closed root 降級。重新導向須重新確認目的文件及來源：同源合理導覽可續接；跨來源／登入導向停止自動定位並保留來源頁。

### 7.2 搜尋預算

- 先掃描目前內容；`MutationObserver` 只針對新增／變更內容節流重新比對，不持續全頁重掃。
- 初始自動搜尋上限為 8 秒、6 次捲動、3 個新定位上下文；任一上限先到就停止。
- 搜尋先利用保存位置作探查，再於有限相鄰範圍搜尋；內層容器僅在可識別時操作。
- 使用者可取消；偵測使用者 wheel、touch、捲動／導覽鍵或切換頁面時停止自動移動，避免搶回控制權。
- 無新增內容或捲動無進展時提早結束。不自動點「下一頁」、切篩選器或遍歷全部相簿。
- 失敗若有可靠位置則回到收藏附近；否則回到搜尋前位置。使用者已接手捲動時不再還原。

這些限制意味著無固定連結且目標尚未載入的 Sportag 類頁面可能只能回到附近；必須如實呈現，不能承諾找到數萬張照片中的任意一張。

## 8. 介面行為

- 圖庫與預覽統一來源開啟邏輯；有定位資料的主要動作稱「回到收藏位置」，舊資料維持「開啟來源頁面」。
- 保留真正的 HTTP(S) anchor href，讓複製連結、鍵盤操作與瀏覽器開新分頁仍可使用。一般啟動走定位流程；修飾鍵、中鍵與右鍵開新分頁若無法可靠綁定工作則維持一般連結，不誤觸重複分頁。
- 來源頁顯示低干擾、可取消的「正在尋找收藏位置…」。成功後短暫外框標示；截圖標示對應區塊而非假裝單張圖片。
- 尊重 reduced motion；不任意搶焦點；提示使用可讀狀態區域，標示不遮擋網站點擊。
- 只恢復位置顯示「已回到收藏附近」；歧義顯示「找到多個相似位置，尚未確認」。
- 失敗提供收藏縮圖、可複製的文字／檔名，以及有效的原始圖片入口；截圖不虛構原圖網址。原始圖片 URL 可能失效，不承諾等同網站購買原圖。
- 不自動重開已關閉的彈窗或恢復已失效的篩選狀態；必要時提示使用者手動操作。

## 9. 模組與實作順序

### 階段 A：資料契約與純邏輯

新增 `source-locator` 相關型別、schema 驗證、URL／文字正規化、候選規則與可信度判定。建議拆為 `source-locator.ts`、`source-locator-match.ts`，保持與 DOM／browser API 解耦。串接 items 與 legacy normalization。

完成條件：定位資料 round-trip 不丟失、舊資料正常、重複與矛盾候選不誤判、query 身份參數保留。

### 階段 B：四種收藏入口擷取

新增 DOM 擷取模組，例如 `source-locator-dom.ts`；將 contextmenu 目標、頁面圖片、區域與可視畫面收藏接到同一模型。對齊截圖座標、內層捲動容器與短效 capture token。

完成條件：框外文字不混入截圖 anchor、不同尺寸視窗／DPR 正確、失敗不影響收藏、切換分頁不保存錯誤截圖或錯誤線索。

### 階段 C：靜態回訪與共同入口

新增背景工作管理及回訪 content 模組，例如 `source-relocation.ts`、`source-relocation.content/index.ts`。接 ready handshake、tab 綁定、狀態回報及圖庫／預覽入口，先完成已載入內容的定位及位置備援。

完成條件：新分頁載入後能找到唯一素材／截圖區塊；兩筆收藏並行不串線；舊資料仍正常開來源。

### 階段 D：動態搜尋、提示與清理

加入節流 observer、有限度捲動、內層容器、取消、超時與標示；補中英文案和所有終止情境。保留 HTTP(S) 來源 anchor 及瀏覽器慣用操作。

完成條件：動態載入可重試，搜尋有上限，使用者操作即停止自動移動，頁面不存在殘留 observer／overlay。

### 階段 E：整合驗證與調校

用固定本機測試頁驗證規則，實際網站只作補充人工檢查，不把網站專屬行為寫成必要條件。根據誤判案例校準門檻與預算；寧可回報附近／未確認，不錯標素材。

全部階段完成才視為首版交付；各階段是內部實作順序，不是將截圖或動態頁面留待不確定的未來。

## 10. 測試與驗收

### 自動測試

- 單元：URL 完整／變體、相同檔名不同目錄、身份 query、中文文字、空線索、截斷、版本與不合法資料。
- 匹配：重複圖片／文字、動態 ID、矛盾證據、多定位點相同區塊、同圖不同卡片與尺寸差異。
- 幾何：部分相交文字、框外內容、sticky header、DPR、視窗縮放、內層容器、位置夾限。
- 儲存：新舊 item、既有 DB 升級、欄位更新保留、去重不覆寫、刪除清理。
- 生命週期：ready race、背景重啟、並行工作、關閉分頁、過期、取消、導覽、錯誤 sender、跨來源導向。
- 動態：延遲載入、虛擬列表節點重用、無新增內容、預算耗盡及使用者介入後不再移動。

先使用現有 Vitest／fake-indexeddb。DOM 及端到端驗證需合適的 DOM／瀏覽器測試環境；在開始該階段前確認現有工具，必要時補最小測試依賴，不用 mock 取代關鍵幾何與擴充套件整合驗證。

### 人工驗收矩陣

| 情境 | 預期 |
| --- | --- |
| 圖片收藏、素材有明確網址 | 正常開來源並找到素材；原圖入口獨立可用 |
| 無詳細頁的照片列表 | 已載入照片能定位；未載入超過預算則附近／失敗，不誤標 |
| 區域截圖只有文字 | 以文字和上下文找到區塊 |
| 截圖含圖片與多段文字 | 多定位點對應同一區塊，恢復相近視窗位置 |
| 可視畫面截圖、頁面寬度改變 | 依內容重新定位，不只照抄 scrollY |
| 重複素材與導覽列文字 | 不任意選第一個候選 |
| 無限捲動／內層捲動 | 可在限制內搜尋，可取消且停止乾淨 |
| 登入、彈窗、篩選未恢復 | 明確降級，不自動操作或誤稱成功 |
| canvas／跨來源 iframe／受限制頁面 | 收藏流程可降級，定位提示能力限制 |
| 舊收藏 | 來源正常開啟，不虛構不存在的定位資訊 |
| 中鍵、修飾鍵與鍵盤 | 不重複開分頁，不破壞連結基本操作 |
| Chrome 與 Firefox | 完成可用流程及 session 儲存差異的降級驗證 |

驗證指令：`npm run test`、`npm run typecheck`、`npm run build`、`npm run build:firefox`。實作完成後才執行並記錄結果；本計畫未執行這些檢查，也不代表功能已通過測試。

首版完成門檻：固定驗收案例中可靠候選不得錯標；圖片與兩種截圖都可保存／回訪；所有無法定位情境可降級；搜尋可中止且有資源上限；舊資料不受損。外部網站成功率僅作人工紀錄，不把有限樣本包裝為普遍保證。

## 11. 後續擴充

首版完成後再評估本機 OCR、截圖視覺特徵比對、跨 frame 的受限定位及使用者手動更新定位點。這些能力沿用 versioned anchor 模型，不引入網站專屬分支；如涉及新依賴、權限或資料傳輸，另行設計與驗證。
