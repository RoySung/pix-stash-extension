# 素材來源回訪與定位：實作與驗證紀錄

## 已實作

- A：version 1 `sourceLocator`、32 KiB／文字／定位點上限與驗證、保守 URL 變體、中文文字正規化、獨立證據與矛盾判定。IndexedDB 維持 v3；建立、更新、去重與 legacy normalization 保留定位資料。
- B：右鍵圖片、頁面圖片、區域截圖、可視畫面截圖共用 DOM 擷取。保存 CSS pixels、DPR、分散定位點與內層捲動位置。範圍內文字使用 Range，排除表單值、editable、隱藏內容與擴充套件 UI。區域確認後隱藏選取 UI，再以同文件短效 token 在截圖前後驗證分頁、網址、視窗、捲動及元素幾何。
- C：圖庫／預覽共用 HTTP(S) 來源連結；一般點擊建立一次性回訪工作，中鍵與修飾鍵維持瀏覽器原生行為。新分頁先建立工作再導覽，以 ready handshake 交付；工作綁定 tab、request、document、來源與期限。舊圖片可用原圖 URL 作基本定位，舊截圖維持正常開來源。
- D：分段 DOM 掃描、open shadow roots、針對變更子樹的 observer、最多 8 秒／6 個探查捲動步驟／3 個額外捲動容器。使用者 wheel、touch、pointer、導覽鍵、切頁與導覽會停止搜尋。找到／附近／歧義／找不到／不支援／取消各有提示；失敗保留縮圖、可複製文字與有效原圖連結。找到後在縮圖／區塊保留 `data-pixstash-active` 藍色外框，直到關閉標示或離開頁面；圖片節點換成別張照片時也會清除。定時器、observer、提示、active 樣式與短暫外框都有清理路徑。
- E：新增純邏輯、儲存、生命週期、擷取綁定與真實瀏覽器固定案例；保守門檻經誤判案例調整。搜尋上限是資源預算，不是網站成功率保證。

## 驗收邊界與尚待人工確認

- Firefox 的頁面定位邏輯與產物打包已驗證。測試環境能暫時安裝附加元件，但 Playwright 導覽其 `moz-extension://` 圖庫頁逾時，尚未完成 Firefox 原生附加元件的端到端驗收；不將 DOM 測試視為該驗收已通過。
- 已在使用者提供的 Sportag `event_id=1204&view=all` 公開相簿，以實際擴充套件完成 5 項回訪檢查。測試的是首批已載入照片與放大視窗；未使用登入、購買、篩選復原或深層未載入照片作成功率評估，不能推廣為任意相簿都可找回。
- 首版擷取與搜尋以頂層文件及 open shadow DOM 為範圍；iframe、canvas、closed shadow root 內部不穿透。缺乏可讀內容時使用正常來源開啟、附近位置與人工線索降級。
- 內層容器自動位置恢復／探查要求可唯一識別的 ID。只剩結構路徑時不冒險移動內層容器；已載入內容仍可藉內容證據與 `scrollIntoView` 找到。
- 不自動登入、開啟彈窗、重播篩選／表單、點擊下一頁或無限捲動。資料僅存本機，未加入 OCR、像素比對或第三方分析。

因此目前狀態為「首版功能已實作，自動驗證通過；Firefox 原生流程與外部網站人工矩陣仍待驗收」，並非宣稱全部人工情境已驗收完畢。

## Sportag 回歸修正（2026-11-08）

實際重現「頁面圖片收藏」失敗：放大視窗與列表同時有相同圖片，舊擷取將重複實例降級成只有 URL 的 weak anchor，回訪時被直接略過。修正後使用語意 dialog 的前景圖片作目標，保留同資源縮圖的可見 alt 識別文字；不依賴網站名稱或網站 selector。

可辨識的 OSS 完整簽名封套更新，只在來源／路徑、其餘資源參數相同且有獨立照片 alt 或上下文支持時接受；保存的完整 URL 不會被刪參數或改寫。`photo_id`、影像處理參數、未知 token、不同目錄仍須保持一致，沒有旁證時不把相同路徑當作可靠命中。

先前 URL-only weak 圖片收藏可在回訪時，依既有原圖 URL 重新確認唯一的精確縮圖；這是暫時比對，不覆寫 item。舊線索若簽名已變且缺乏身份旁證，仍須降級；重新建立收藏才會保存新增的可見身份線索。

已確認新的前景預覽回歸在移除修正後會失敗，恢復後通過；簽名封套單元案例亦已先失敗再修正。實際 Sportag 驗證方法見 `tests/source-relocation/sportag.mjs`。

## 回訪頁缺少定位程式（2026-11-09）

依使用者截圖固定照片 ID 29340315，將實站驗證從背景 API 呼叫改成真正點圖庫的來源連結後，重現「新分頁正確、沒有外框且沒有定位提示」。目前開發產物的 manifest 未靜態列出 content scripts；當自動註冊缺失時，收藏原頁仍可靠既有按需注入成功，新回訪分頁卻沒有任何程式向背景領取定位工作。先前只測背景 API 與正常自動載入的案例，未涵蓋這個環境。

修正後在有短效定位工作的分頁載入完成時，先 probe 已載入程式；沒有接收端時，只對綁定的回訪 tab／頂層 frame 注入既有程式，再由 ready handshake 領取工作。不增加權限、不向網站網址放入收藏資料，也不覆寫重複收藏或組織資料。

另補上已確認的 URL 通知順序問題：ready 已綁定的同一文件 URL 再次被回報，不應誤判成使用者導覽而取消工作；改存文件網址並忽略同一 URL 的延遲通知。新的回歸先失敗，修正後通過。

驗證包含 79 項單元測試、正常圖庫點擊、刻意移除自動 content script 的 4 個本機整合案例，以及同樣移除自動載入條件下的 5 個 Sportag 實際擴充套件案例。實站流程先收藏、再次收藏確認 duplicate，再點圖庫連結回訪同一張照片；同時驗證 active 樣式、關閉與過期簽名旁證。

## 通用照片連結驗證與重新尋找（2026-11-09）

- 收藏放大照片時，記錄圖片外層或緊鄰區塊內已存在的同來源 HTTP(S) 連結，最多 3 個；不猜測路由、不呼叫網站私有 API。移除舊有網站名稱／專屬 selector 的圖片擷取分支，改以可見語意 dialog 或覆蓋視窗的固定圖片層辨識預覽。
- 回訪先嘗試已驗證連結或第一個觀察到的候選連結。候選頁必須有明顯主要圖片，且實際下載內容的 SHA-256 與收藏圖片完全一致，才能顯示找到與 active 外框，並保存驗證後連結。最多驗證 3 個圖片 URL；工作綁定分頁、頂層文件、request、網址及期限；驗證中導覽不能復活舊工作。
- 圖庫主要動作在驗證後變為「開啟收藏照片」，另保留「開啟原相簿／來源頁」。候選驗證失敗會回到原來源。內容重新壓縮、不同尺寸、無可用連結或下載失敗都不能視為驗證成功；不保證所有不換網址的分頁網站都能直接還原。
- 僅還原捲動位置時，提示明確寫出尚未找到收藏內容；使用者切頁後可按「重新尋找」，啟動新的有限搜尋。搜尋失敗不再用附近位置暗示已找到照片。
- 舊收藏若缺少連結，可在原頁放大同一張照片並再次儲存：只有相同圖片內容才補入觀察到的連結，不建立重複項目，保留原註記、標籤與定位證據。

本機瀏覽器案例涵蓋不同圖片 URL 但相同檔案、錯誤連結顯示不同檔案時回退、已驗證連結成為主要 href、保留原來源，以及手動切頁後重新尋找。Zsport 實站案例明確等待第二頁出現初始清單不存在的照片，再放大收藏、點擊圖庫連結驗證。實站範例是通用規則的驗證資料，正式程式沒有網站專屬判斷。
